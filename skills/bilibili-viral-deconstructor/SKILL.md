# B站爆款视频拆解 Skill

## 你在帮谁做这件事

你在辅助一个做**短视频 / 知识付费内容**的创作者做「对标拆解」。他刷到一条爆了的 B 站视频，
想知道**它为什么能爆**，并把背后的套路提炼成自己能复用的方法论——不是抄这一条，而是拆出骨架。

他要的不是"这视频不错"这种废话，而是一份**指证到具体证据**（哪句话、第几秒、哪个数据）、
能直接拿去指导自己创作的拆解报告。

---

## 整体流程

1. **取数据**（见下）：拿到字幕（口播稿）+ 播放/三连/粉丝数据 + 标题/封面。
2. **按八层框架拆**：读 `references/methodology.md`，逐层分析，每个判断都指证到证据。
3. **产出两份交付物**（默认都要）：
   - **HTML 报告**：以 `assets/report-template.html` 为骨架生成单文件 HTML（可扫视的卡片信息图）。
   - **详细 Markdown 文档**：同样八层结构，但用表格/引用/列表把每层写透、证据更全（适合存档、二次编辑、发给别人）。
   两份内容口径一致，HTML 偏"扫一眼吸收"、Markdown 偏"完整留底"。同名不同后缀，保存到同一目录。
4. **保存并打开**：HTML 用 `open` 打开；两个文件路径都告诉用户。
5. 对话里只回："报告已生成：<HTML路径> 和 <MD路径>" + 1-2 句最关键的定性（如"叫好不叫座，
   高收藏率但没起量；可复用的是它的标题三钩叠加"）。**不要**把报告内容在对话里整段复述。

## 第一步 · 取数据

字幕是拆解的核心原料（口播文案），数据用于第一层分析。取数脚本 `scripts/fetch_bili.py`
复刻了 B 站的公开接口，纯 Python 标准库，无需 pip 安装。

> 🔑 **关于 SESSDATA（每个使用者填自己的）**：B 站 CC/AI 字幕只在登录态返回，需要你**自己 B站账号**的
> `SESSDATA` Cookie。这是你的私人登录凭证，**请用你自己的、不要用别人的**，也不要把它提交到 Git 或公开分享。
> 第一次用时，复制 `.env.example` 为 `.env` 填进去（`export $(cat .env)` 后脚本会自动读 `BILI_SESSDATA`），
> 或每次用 `--sessdata` 直接传。怎么拿见 `assets/subtitle-extractor-userscript.md`。
> 没有 SESSDATA 也能用——公开数据照拿，字幕走油猴脚本导出 SRT 的本地路径。

**根据用户给的东西选路径：**

- **给了视频链接 / BV号**：跑脚本取数。字幕需要登录态，分情况：
  ```bash
  # 有 SESSDATA（推荐，能一并拉到在线字幕）：
  python scripts/fetch_bili.py "<链接或BV号>" --sessdata "<SESSDATA>" --out-dir <工作目录>
  # 没有 SESSDATA：仍能拉到公开的播放/三连/粉丝/标题/封面，字幕走下面的本地导入
  python scripts/fetch_bili.py "<链接或BV号>" --out-dir <工作目录>
  ```
  `SESSDATA` 也可放环境变量 `BILI_SESSDATA`。拿 SESSDATA 的方法见 `assets/subtitle-extractor-userscript.md`。

- **给了字幕文件**（用户已用油猴脚本导出 SRT/txt，或直接贴了口播稿）：用 `--srt` 传入，
  脚本会解析字幕并尽量补上公开数据：
  ```bash
  python scripts/fetch_bili.py "<链接或BV号>" --srt <字幕文件> --out-dir <工作目录>
  ```
  如果用户是直接把口播文字贴在对话里、没有视频链接，就把这段文字存成一个 `.txt` 再 `--srt` 传入，
  或直接拿对话里的文字做第五~八层分析（这几层只需要口播稿）。

- **拿不到字幕**（没登录、视频无字幕）：脚本会在 SUMMARY 里提示。这时告诉用户两条路：
  ① 提供 SESSDATA；② 用油猴脚本（`assets/subtitle-extractor-userscript.md`）在网页导出 SRT 再传进来。
  在拿到字幕前，可以先用已有数据做第一~三层的数据/选题/标题分析。

**读 SUMMARY**：脚本最后会在 stdout 打印一段 SUMMARY（播粉比、各项互动率、字幕条数等），
和生成的 `<bvid>_data.json`（全量结构化数据）、`<bvid>_subtitle.txt`（带时间戳口播稿）。
先看 SUMMARY 再读 json/txt 做深度拆解。

> 优雅降级是原则：数据缺哪块，对应那层就如实写"数据缺失，建议补 XX"，不要脑补一个播放量或互动率。

## 第二步 · 按八层框架拆解

完整框架在 `references/methodology.md`，**动手前先读一遍**。八层 + 总结概览：

1. **数据爆火**：播粉比、互动比（点赞/收藏/投币/评论率），判断它爆的程度与类型（靠什么爆）。
2. **选题**：受众面 / 时效性 / 信息差三维评级 + 切入角度。
3. **标题封面钩子**：拆钩子类型（悬念/数字/反常识/身份代入/情绪）组合，提炼标题公式。
4. **开头黄金 3 秒**：引用开头原话 + 留人策略 + 开头模板。
5. **内容结构**：口播按时间线分段，识别叙事结构（总分总/问题-分析-方案/故事线）+ 衔接手法。
6. **中间钩子节奏**：钩子时间轴（时间戳+话术+类型），看间隔是否均匀（约 30-60 秒一个）。
7. **焦虑点情绪**：情绪触发点清单（时间戳+话术+情绪类型）。客观拆解手法，不是教人坑人。
8. **结尾转化**：引导三连/留悬念/引导关注或私域的设计。
9. **可复用方法论**（最值钱）：汇总出选题角度、标题公式、开头模板、钩子节奏、情绪话术、结构框架。

**拆解的灵魂**：每条结论都要能指出"凭哪句话/第几秒/哪个数据"。指不出证据宁可写"信息不足"。
口播稿很长时，重点抓开头、各段过渡句、转折句、情绪词，不必逐字复述。

## 第三步 · 生成两份交付物

默认**同时**产出 HTML 报告和详细 Markdown 文档，两者内容口径一致、各有侧重。
文件名统一为 `视频拆解-<UP主或一句话主题>`，同名不同后缀，存到同一目录（默认用户桌面 `~/Desktop`，
或用户指定的工作目录），最后把两个路径都告诉用户，并 `open` 打开 HTML。

### A. HTML 报告（扫一眼吸收）

一个**单文件、可直接运行的精美 HTML**——苹果发布会风、纯黑卡片化。

1. **读模板** `assets/report-template.html`：它是完整可运行的成品，已实现全部设计规范
   （CDN 引入、Tailwind 配置、品牌色、主卡/迷你卡、Chart.js、滚动淡入、复制按钮），
   并按八层结构排好了版块。**以它为骨架**，照搬技术骨架与 CSS/JS，只替换文字内容与图表数据。
2. 保存为 `视频拆解-<主题>.html`。

### B. 详细 Markdown 文档（完整留底）

同样的八层结构，但写得**更透、证据更全**，适合存档、二次编辑、转发给别人。规范：

- 开头一个**信息表**（视频/UP主/粉丝/BV号/时长/赛道/一句话定性）。
- 每一层一个 `##` 小节，多用**表格**（数据层、节奏层、情绪层的"时间戳+话术"特别适合表格）、
  引用块放原话、列表放要点。比 HTML 卡片能承载更多细节和推理过程。
- 结尾"可复用方法论"用一个**公式对照表**（模块 → 可照搬的公式）+ 一段"给你的对标启示"。
- 数据缺失、节奏隐患、转化缺口等都如实写明，和 HTML 口径一致。
- 保存为 `视频拆解-<主题>.md`。

### 设计规范（硬性，照模板执行，勿偏离）

- **单文件**：HTML/CSS/JS 全在一个 .html，只用 CDN（Tailwind、Font Awesome、Chart.js）。
- **风格**：苹果官网/发布会风，简洁、信息层级清晰。**背景纯黑 `#000`**。
- **卡片布局**：每一层 = 一张主卡（深灰 `#1a1a1a`、`rounded-2xl`、`border #333`），左上角放超大层号（01–08）；
  主卡内嵌**迷你卡片网格**（`#222`、`rounded-lg`），响应式 `grid-cols-1 sm:grid-cols-2 lg:grid-cols-4`，
  中大屏每行 3-5 个。要点提炼成迷你卡，**一卡一要点**，避免大段文字。
- **唯一高亮色**：默认 **B站粉 `#FB7299`**；若视频内容有明显主品牌，可换其官方 VI 色。
  全篇只用这一个高亮色（关键文字、大数字、图标、图表、边框），在 `tailwind.config.colors.brand` 设置。
- **科技感渐变**：只对高亮色做透明度渐变（`.7→.3`），作卡片微妙底色，**禁止多色渐变**。
- **强视觉层级**：迷你卡里——有关键数字就把**数字放顶部** `text-5xl/6xl font-bold` 高亮色，下方小字解释；
  概念性要点就用 3-5 字加粗中文短语 `text-3xl/4xl`，下方小字给细节。可审慎加一行极简英文副标题
  `text-xs text-gray-500`（如 "Favorite Rate""Info Gap"），增 design 感，别每张都加。
- **图标**：Font Awesome 线框风为主，主标题旁/迷你卡标题处/列表前缀。**严禁 Emoji 当功能图标**。
- **图表**：Chart.js，配色贴合暗黑主题与高亮色。适合放图的地方：第一层互动率对比（条形图）、
  三连构成、选题三维雷达等——**有合适数据就放，别硬凑**。
- **动画**：Intersection Observer 滚入淡入+上滑，网格项交错延迟。
- **响应式**：强制，手机/平板/桌面都好看。

### 让报告适配这条视频，而不是套死模板

模板是骨架不是填空题。钩子有几个标几个，情绪触发点有几条放几张卡，结构该 3 段就 3 段。
数据缺失的层，在卡片里诚实写"数据缺失，建议补 XX"，不要编造播放量/互动率。
**可复用方法论**那一节是整份报告的落点，务必写实、写具体（"反常识+数字+身份代入"这种能直接照搬的公式，
而不是"标题很吸引人"这种空话）。

## 几个尺度

- **基于证据，不要编**：每个判断指得出"凭哪句话/第几秒/哪个数据"。
- **数据缺失就如实标**：拿不到的指标写"数据缺失"，别脑补。
- **落点是可复用**：用户拆解的目的是对标自己创作，所以最后一节的"骨架"必须能直接拿去用。
- **诚实定性**：如果这条其实没那么"爆"（播粉比不高），要敢说，并指出它可能只是粉丝基本盘。
